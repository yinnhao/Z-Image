# Z-Image Pipeline 符号约定与时间步映射分析

本文档解析 `src/zimage/pipeline.py` 中两处看似"反直觉"的代码：

```python
timestep = (1000 - timestep) / 1000   # 第 223 行
noise_pred = -noise_pred.squeeze(2)    # 第 274 行
```

---

## 1. Flow Matching 基础回顾

Flow Matching 的核心——用直线连接数据和噪声：
一切基于加噪方向

```
x_t = (1 - t) * x_0 + t * ε
```

其中 `t ∈ [0, 1]`，`x_0` 是干净图像，`ε` 是纯高斯噪声。

- `t=0` 时，`x_t = x_0`（干净图像）
- `t=1` 时，`x_t = ε`（纯噪声）

速度场对 t 求导：

```
v = dx_t/dt = -x_0 + ε = ε - x_0 
```

这是线性插值对 t 求导的数学结果。方向从 x_0 指向 ε（t 增大时，从干净走向噪声）。

---

## 2. Z-Image 的非常规选择

Z-Image 没有采用社区标准约定，而是选择了一套**以"去噪"为中心**的设计哲学：

### 2.1 预测目标：`x_0 - noise`（去噪方向）

训练代码（`train_lora.py` 第 486 行）：

```python
target = latents - noise  # 即 x_0 - ε
```

| | 标准 Flow Matching 约定 | Z-Image 约定 |
|---|---|---|
| 预测目标 | `ε - x_0`（加噪方向） | `x_0 - ε`（去噪方向） |
| 物理含义 | "噪声与数据的差" | "数据与噪声的差" |
| 语义 | 模型回答"噪声在哪" | 模型回答"干净图像在哪" |

### 2.2 时间步约定：0=噪声，1=干净

训练代码（`train_lora.py` 第 494 行）：

```python
model_timestep = 1 - sigma  # sigma=1(噪声)→模型收到0, sigma=0(干净)→模型收到1
```

| | 常规模型 | Z-Image |
|---|---|---|
| 归一化方式 | `sigma = t / 1000` | `(1000 - t) / 1000` |
| 1000（噪声）→ | **1**（噪声水平高） | **0** |
| 0（干净）→ | **0**（噪声水平低） | **1** |
| 语义 | "当前噪声有多大" | "去噪完成了多少" |

### 2.3 两个选择是自洽的

Z-Image 的设计哲学一致地站在"去噪"视角：

1. 时间步：0→1 表示"从脏到干净"（去噪进度）
2. 预测目标：`x_0 - noise`（去噪方向，"我要往哪走才能得到干净图片"）

而常规模型站在"加噪"的视角——"噪声有多大，噪声是什么"。

---

## 3. 为什么推理 Pipeline 需要取负号？

### 3.1 Scheduler 的 step 方法

`src/zimage/scheduler.py` 第 137-138 行：

```python
dt = sigma_next - sigma          # sigma 递减，所以 dt < 0
prev_sample = sample + dt * model_output  # 等价于 sample - |dt| * model_output
```

采样过程中 sigma 从大（~1）到小（0），所以 `dt` 始终是负值。

### 3.2 推导为什么需要取负

Scheduler 做的事情：

```
x_next = x_t + dt * v
      = x_t - |dt| * v     (因为 dt < 0)
```

如果 `v = ε - x_0`（标准约定，指向噪声方向），那么：

```
x_next = x_t - |dt| * (ε - x_0)  →  向 x_0 靠近 ✓
```

但 Z-Image 模型输出的是 `x_0 - ε`（去噪方向），直接传给 scheduler 会导致方向反了：

```
x_next = x_t - |dt| * (x_0 - ε)  →  远离 x_0 ✗
```

所以需要取负：

```python
noise_pred = -noise_pred  # 将 (x_0 - ε) 转换为 (ε - x_0)
```

转换后传给 scheduler 就正确了。

---

## 4. 时间步转换详解

Scheduler 产生的 `timesteps` 范围是 1000 → 0（diffusers 风格）：
- `t = 1000` 表示纯噪声
- `t = 0` 表示干净图像

模型期望的时间步：
- **0 = 纯噪声**
- **1 = 干净图像**

转换公式：

```python
timestep = (1000 - timestep) / 1000
```

| scheduler 的 t | 转换后传给模型 | 含义 |
|---|---|---|
| 1000（纯噪声） | (1000-1000)/1000 = **0** | 模型理解为"当前是纯噪声" |
| 500（半噪声） | (1000-500)/1000 = **0.5** | 模型理解为"去噪进行了一半" |
| 0（干净） | (1000-0)/1000 = **1** | 模型理解为"已经干净了" |

---

## 5. 为什么 Z-Image 选择这套非常规约定？

大概率是**继承自上游视频生成模型的设计**。证据：

- 代码中 `unsqueeze(1)` 为 latent 添加 frame 维度（兼容视频模型接口）
- 模型输入输出都是 list 形式（支持多帧）
- Z-Image 的 transformer 架构来自一个视频模型（可能是万象/HunyuanVideo 一类）

上游模型选了"去噪进度"这套约定，Z-Image 复用架构时继承了下来。没有必要为了"对齐社区惯例"而改动模型内部逻辑。

代价就是跟 diffusers 的 scheduler 对接时，需要两处适配：
1. 时间步翻转：`(1000 - t) / 1000`
2. 输出取反：`-noise_pred`

## 6. 总结

```
┌─────────────────────────────────────────────────────────────────┐
│                    推理 Pipeline 数据流                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Scheduler timestep (1000→0)                                    │
│       │                                                         │
│       ▼ (1000 - t) / 1000                                       │
│  Model timestep (0→1, 去噪进度)                                  │
│       │                                                         │
│       ▼ Transformer forward                                     │
│  Model output: x_0 - ε (去噪方向)                                │
│       │                                                         │
│       ▼ 取负号 (-)                                               │
│  Scheduler input: ε - x_0 (标准 velocity)                       │
│       │                                                         │
│       ▼ scheduler.step (sample + dt * v, dt<0)                  │
│  Updated latent (向 x_0 靠近)                                    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

两处适配的本质：**Z-Image 模型用"去噪视角"设计，diffusers scheduler 用"加噪视角"设计，需要在接口处翻转符号以对齐。**
